## 1. Architecture

**Chosen runtime: pure-Lua KOReader plugin, no Node sidecar.** See `architectureDecision` for the deciding evidence. In one line: KOReader already ships LibreSSL 4.3.2 (TLS + libcrypto via LuaJIT FFI) and rapidjson, which together cover network + crypto + JSON in-process — the three things a sidecar would have been for.

The plugin reproduces `scripts/sync-core.mjs` exactly via FFI into the already-loaded `libcrypto`, talks HTTPS through bundled LuaSocket/LuaSec, and renders with KOReader's built-in widgets. `scripts/sync-core.mjs` is the conformance oracle: every crypto/selection path is validated by round-tripping fixtures through it (Node↔Lua), the same way the repo already round-trips Node↔browser.

## 4. Phase 1 — read-only sync (implementable step sequence)

Goal: open the plugin, show today's checklist with live completion status (read-only), today's meditation point, and the day's rosary. No writes.

> **Recipe-verified:** the §4.2–§4.3 derivation + decrypt was checked byte-for-byte against `sync-core.mjs:16-125` and `syncCrypto.ts`. It produces the exact UTF-8 `JSON.stringify(SyncState)` the phone wrote. The notes below are plumbing corrections, not recipe changes.

### 4.1 Constants (hard-code, from `sync-core.mjs`)
```
AUTH_SALT       = "planoflife-sync/auth/v1"   -- 23 UTF-8 bytes (verified count)
AUTH_ITERS      = 310000   -- bearer token derivation
ENC_ITERS       = 600000   -- AES key derivation  (do NOT swap these two)
KEY_LEN         = 32          -- bytes (AES-256)
IV_BYTES        = 12
GCM_TAG_BYTES   = 16          -- WebCrypto default 128-bit tag, APPENDED to ct
SYNC_SCHEMA     = 3
-- GCM ctrl (LibreSSL == OpenSSL): SET_IVLEN=0x9, GET_TAG=0x10, SET_TAG=0x11
-- No AAD anywhere — do NOT pass additionalData on Update or the tag check fails.
```

### 4.2 Key derivation (`lib/crypto.lua`, FFI into the already-loaded libcrypto)
Reuse `ffi.loadlib("crypto","57")` (same handle `ffi/crypto.lua` uses) and **additively** cdef only the new prototypes. Do NOT re-typedef `EVP_CIPHER`/`EVP_CIPHER_CTX`/`ENGINE` (LuaJIT errors on duplicate *struct/type* definitions; `ffi/crypto_h.lua` already declares them). Re-declaring a *function* prototype with an identical signature is tolerated by LuaJIT, but the safe pattern is `pcall(ffi.cdef, ...)` per block so a pre-existing declaration can't abort load.

```lua
local ffi = require("ffi")
local C = ffi.loadlib("crypto", "57")   -- verify soname on device (Risk #1)
ffi.cdef[[
  typedef struct evp_md_st EVP_MD;
  const EVP_MD *EVP_sha256(void);
  int PKCS5_PBKDF2_HMAC(const char*, int, const unsigned char*, int, int,
                        const EVP_MD*, int, unsigned char*);
  const EVP_CIPHER *EVP_aes_256_gcm(void);
  /* Context lifecycle: MUST be available (see note below). KOReader's
     ffi/crypto_h.lua may already declare these; pcall-guard the cdef. */
  EVP_CIPHER_CTX *EVP_CIPHER_CTX_new(void);
  void EVP_CIPHER_CTX_free(EVP_CIPHER_CTX*);
  int EVP_DecryptInit_ex(EVP_CIPHER_CTX*, const EVP_CIPHER*, ENGINE*,
                         const unsigned char*, const unsigned char*);
  int EVP_DecryptUpdate(EVP_CIPHER_CTX*, unsigned char*, int*, const unsigned char*, int);
  int EVP_DecryptFinal_ex(EVP_CIPHER_CTX*, unsigned char*, int*);
  int EVP_CIPHER_CTX_ctrl(EVP_CIPHER_CTX*, int, int, void*);
  int RAND_bytes(unsigned char*, int);    -- Phase 2
  int EVP_EncryptInit_ex(EVP_CIPHER_CTX*, const EVP_CIPHER*, ENGINE*,
                         const unsigned char*, const unsigned char*);  -- Phase 2
  int EVP_EncryptUpdate(EVP_CIPHER_CTX*, unsigned char*, int*, const unsigned char*, int);
  int EVP_EncryptFinal_ex(EVP_CIPHER_CTX*, unsigned char*, int*);
]]

local function pbkdf2(pass, salt, iters, outlen)        -- HMAC-SHA256
  local out = ffi.new("unsigned char[?]", outlen)
  assert(C.PKCS5_PBKDF2_HMAC(pass, #pass, salt, #salt, iters,
                             C.EVP_sha256(), outlen, out) == 1)
  return ffi.string(out, outlen)                         -- raw 32-byte string
end
```

> **Plumbing note (FFI context allocation) — verify in the spike.** The GCM decrypt/encrypt sequence needs an allocated `EVP_CIPHER_CTX` via `EVP_CIPHER_CTX_new()` and must `EVP_CIPHER_CTX_free()` it on **every** path, including the `EVP_DecryptFinal_ex → rv==0` (wrong-passphrase/tampered) failure path, or it leaks. Whether KOReader's bundled `ffi/crypto_h.lua` already exports these *functions* (not just the opaque types) is **unverified** — KOReader internals aren't in this repo. The smoke-test spike (§7 step 2) must confirm; if absent, the additive cdef above supplies them. Wrap each FFI crypto op so `free` runs in a `finally`-style cleanup.

> **Plumbing note (SET_IVLEN redundant).** `EVP_CIPHER_CTX_ctrl(SET_IVLEN, 12)` is a no-op because 12 is the GCM default IV length. Keep it for clarity; no behaviour change.

- `authToken = base64url_nopad( pbkdf2(passphrase, AUTH_SALT, 310000, 32) )`. base64url = standard b64 then `+`→`-`, `/`→`_`, strip `=`. (Independent of the account salt — can be computed before GET.)
- `encKey = pbkdf2(passphrase, saltBytes, 600000, 32)` where `saltBytes` comes from the GET response (`base64decode(salt)`).

Base64: use bundled LuaSocket `mime` (`mime.b64`/`mime.unb64`) or `ffi/sha2.lua`'s helper; **strip any whitespace defensively before decoding**. The server stores exactly what `btoa`/`Buffer` produced (standard, padded, no newlines), so a strict standard-base64 decoder that requires padding is sufficient — but tolerate stray whitespace so a chunked/newline-wrapped transport can't corrupt the input. **Cache both `authToken` and `encKey` in a module-level Lua var for the session** (never write the key to disk).

### 4.3 GET /state + decrypt
1. `NetworkMgr:runWhenOnline(function() ... end)` to gate on connectivity.
2. `socket.http` GET (wallabag pattern), `Authorization: Bearer <authToken>`, `socketutil` timeouts, no caching. For cert validation point LuaSec at bundled `certifi` `cafile` (optional — payload is independently AES-GCM authenticated; validate anyway).
   - `200` → body `{ version, blob, salt }` via `rapidjson.decode`.
   - `401` → wrong passphrase token → show InfoMessage "Wrong passphrase".
   - `blob==nil or salt==nil` → empty account → empty state.
3. Persist to `LuaSettings`: `account_salt` (first time), `version`, `cached_blob` (the encrypted base64 — safe to store), `last_sync_ts`.
4. Derive `encKey` from `saltBytes` (if not already cached this session).
5. Decrypt (matches WebCrypto tag-appended layout, `sync-core.mjs:113-125`):
   - `data = base64decode(blob)` (standard base64, padded).
   - `iv = data[1..12]`, `tag = data[#data-15 .. #data]` (last 16 bytes), `ct = data[13 .. #data-16]` (ciphertext only). Arithmetic: `12 + (N-28) + 16 = N`.
   - `ctx = EVP_CIPHER_CTX_new()`
   - `EVP_DecryptInit_ex(ctx, EVP_aes_256_gcm(), nil, nil, nil)`
   - `EVP_CIPHER_CTX_ctrl(ctx, 0x9 /*SET_IVLEN*/, 12, nil)`
   - `EVP_DecryptInit_ex(ctx, nil, nil, key, iv)`
   - `EVP_DecryptUpdate(ctx, out, &outl, ct, #ct)`
   - `EVP_CIPHER_CTX_ctrl(ctx, 0x11 /*SET_TAG*/, 16, tag)`
   - `rv = EVP_DecryptFinal_ex(ctx, out+outl, &finl)` → `rv==0` ⇒ wrong passphrase / tampered ("Decryption failed").
   - `EVP_CIPHER_CTX_free(ctx)` on **all** exits (success and `rv==0`).
   - plaintext = `out[0..outl+finl]`; `state = rapidjson.decode(plaintext)`.
6. **Courtesy schema guard (read):** if `state.schema > 3`, show "App is newer than this plugin — update" and still render best-effort (read-only can't corrupt anything). The matching **write-side** guard (which must *block*, not warn) lives in §5.2.

### 4.4 Build & render today
`today = os.date("%Y-%m-%d")` (local — matches the phone's `startOfDay(new Date())` local date). Then via `lib/selection.lua`:
- `plan = buildDailyPlan(state.data.categories, state.data.practices, today)`.
- For each practice: `done = isRecordCompleted(find(state.data.dailyRecords, dailyRecordId(today, p.id)))`.
- Honor `settings["settings-hide-completed"]` for display only.

**Widgets** (from the koreader-ui map):
- Checklist → `Menu` (`frontend/ui/widget/menu.lua`), full-screen (`is_borderless=true`, width/height = `Screen:get*`), each row `text = name`, `mandatory_func = function() return done[p.id] and "✓" or "▢" end` (the generic `Menu` does NOT render `checked`; the glyph in `mandatory_func` is the verified approach, glyphs taken from `CheckMark`). Category headers as `dim`/`bold` separator rows showing `completed/total`. `hold_callback` (or `callback` in read-only) → open the reader for that practice. First show: flashing `ui`. Tap repaint later (Phase 2): `Menu:updateItems()` then `setDirty(menu, "ui")`.
- Practice text / novena → `TextViewer` (`text_type="book_info"`, `add_default_buttons=true`, `justified=true`). Light markup → set `text_format="md"`/`"html"` to use `ScrollHtmlWidget`. Resolve novena text with `resolveNovenaReaderText(practice, today)` before generic bundled text.
- **No auto-mark on open in Phase 1** — the phone's `PracticeReader` auto-marks via `markCompleted` (`PracticeReader.tsx:72-75`); the Kindle must replicate ZERO writes here. Opening any reader is a pure read.

### 4.5 Meditation point (display-only)
- For each slot the Kindle shows (start with `manha`; `tarde` optional): `key = meditationDayKey(today, slot)` (morning = bare date; afternoon = `${date}:tarde`).
- Find `state.data.meditationDays` row with `id == key`. If present → `n = row.pointNumber`; render three `TextViewer`s (or one composed view) for Caminho/Sulco/Forja via `getEscrivaPoint(points, book, n)` from bundled `data/escriva_points.json`; `n` above a book's max → "(sem ponto)".
- **If absent → empty state. Do NOT draw** — a draw is a synced write (gated to "today" on the phone too). Drawing is a Phase-2 decision (default: never draw on Kindle; display only).

### 4.6 Rosary (purely local, nothing to sync)
- `weekday = os.date("*t").wday - 1` (Lua wday is 1=Sun..7=Sat → subtract 1 to match JS `getDay()` 0=Sun..6=Sat).
- Derive the prayed set from `vocalDays` in `data/rosary_contemplation.json`; contemplate the other 3 in `SET_ORDER = {gozosos, luminosos, dolorosos, gloriosos}` → flatten to 15 mysteries. **Ignore `nonDaySetByWeekday` (dead field).**
- Per-mystery: pick one random Escrivá quote + one random painting (`math.random`, re-roll on a shuffle button). Ephemeral, never persisted, never synced.
- Render: custom `FrameContainer` + `ImageWidget` + `ScrollTextWidget` carousel (swipe to advance). Use `full` refresh on image screens.

### 4.7 Key caching & offline
- **Memory (session):** `authToken`, `encKey`, decoded `state`. Cleared on `onClose`/`onSuspend`.
- **Disk (`settings/planoflife.lua` via LuaSettings):** `worker_url`, optional `passphrase` (see runbook — default on for a personal device, like wallabag), `account_salt`, `version`, `cached_blob` (encrypted), `last_sync_ts`, plus the Phase-2 `write_queue`.
- **Offline open:** if `NetworkMgr:isOnline()` is false (or GET fails), decrypt `cached_blob` with the session `encKey` and render with a "stale, last synced <ts>" banner. If the plugin cold-started (no session key) and the passphrase is stored, re-derive; if not stored, prompt for it once. No network → no error spam, just stale view.
- **Cheap freshness probe:** on subsequent opens use `GET /state?meta=1` (returns `{version, blob:null, salt}`, `index.ts:144-154`) and only do the full blob GET when `version` advanced past the cached one.

## 5. Phase 2 — writes (the dangerous part: SAFE toggle protocol)

The model is **snapshot last-write-wins with NO tombstones**. The app rebuilds a full snapshot from its own 15-table list (`applyState.ts:39-94`); **the Kindle must NEVER do that** — it would strip examen (phone-only), career, and any unknown future table. The Kindle's safe strategy is **edit the freshly-fetched remote blob in place**, which auto-preserves every key it doesn't model and sidesteps schema stripping. The Kindle also never needs to run `mergeStates`: because every push starts from the freshest remote, the PUT body = remote + our one edit, so other devices' rows are never present-to-be-dropped. (`mergeStates` only matters on the *phone's* 409 path, `SyncProvider.tsx:265-275`, which the Kindle does not run.)

> **Verified sound:** optimistic concurrency on the Worker (`index.ts:186-189`, 409 on `baseVersion != KEY_VERSION`) closes the read-modify-write window; edit-in-place preserves untouched keys verbatim; absolute-target 409 retry is correctly reasoned; deterministic ids mean zero UUID minting. The fixes below close the remaining data-loss gaps (timestamp ordering, nested empty-arrays, journal ACK, write schema guard).

### 5.1 Local journal (instant taps)
- On a checklist tap: compute the **absolute target** (the desired final state, not a flip): `target = not done[p.id]`. Update in-memory `done[p.id]=target`, `Menu:updateItems()` + `setDirty(menu,"fast")` for an instant, flash-free e-ink toggle.
- Append/replace an intent in the LuaSettings `write_queue`, keyed by `recordId = dailyRecordId(today, p.id)`:
  `{ recordId, date=today, practiceId=p.id, target=bool, enqueuedAt=<monotonic-unique> }`.
  Keying by `recordId` means re-tapping the same row before a flush just overwrites the intent (idempotent, no double-flip). **`enqueuedAt` MUST be unique per (re)tap** (e.g. `os.time()*1000 + a per-process counter`, or `ffi/util.gettime()` usec) — it is the identity token the ACK step (§5.2 step 8) compares to avoid dropping a re-tap that lands during a flush. `store:flush()` so a crash/suspend can't lose it.

### 5.2 Background flush: pull → edit-in-place → push
Trigger on: explicit "sync now", checklist close, `onResume`, `onNetworkConnected`, and a light `scheduleIn(15*60,...)` loop while awake (timers don't run while the device sleeps — §9). Gate with `NetworkMgr:runWhenOnline`. Then, for the snapshot of queued intents:

1. `GET /state` → `{ version, blob, salt }`. `baseVersion = version`.
2. If `blob==nil` → **abort the push** (empty account; the phone has never pushed). Do NOT mint a fresh snapshot from the Kindle (it lacks the full table set). Keep the queue; surface "no remote state yet".
3. Decrypt `blob` → `state` (full Lua table). **Do not add or remove any key. Do not change `state.schema`.**
4. **Write-side schema guard (blocking).** If `state.schema` (a number) `> SYNC_SCHEMA` (3): **abort the push and keep the queue intact**, surface "App is newer than this plugin — update before syncing writes". The rapidjson round-trip could silently corrupt unknown nested structures the conformance test never covered (see step 6). This mirrors the phone/CLI hard refusal (`assertKnownSchema`, `sync-core.mjs:158-168`, `types.ts:101-106`) — the Kindle must not blindly re-encode-and-PUT an unknown-shape blob.
5. `now = utcIsoMillis()` — a UTC ISO-8601 string **byte-identical in shape** to JS `Date.toISOString()`: `YYYY-MM-DDThh:mm:ss.sssZ`, with milliseconds **zero-padded to exactly 3 digits**, fresh per attempt. For each queued intent, apply the **absolute target** to `state.data.dailyRecords`:
   - If a row with `id == recordId` exists: set `isCompleted = target`, `completedAt = target and now or json.null`, `updatedAt = now`.
   - Else append `{ id=recordId, date, practiceId, isCompleted=target, completedAt=target and now or null, updatedAt=now }`.
   - `date` MUST be the local `YYYY-MM-DD`; `completedAt`/`updatedAt` are UTC. Mirrors `useDailyRecords.ts:14-36` exactly so the app's `newerUpdatedAt` merge resolves identically.

   **`utcIsoMillis()` (load-bearing — see §9 Risk):** `merge.ts:30-31` resolves conflicts by **lexical string `>=` compare** of `updatedAt`. Lexical order equals chronological order ONLY if ms is always 3 digits. `os.date("!%Y-%m-%dT%H:%M:%S")` has no sub-second field, so derive ms from a sub-second clock and pad:
   ```lua
   local util = require("ffi/util")
   local function utcIsoMillis()
     local s, us = util.gettime()                  -- seconds, microseconds
     local ms = math.floor(us / 1000)
     return os.date("!%Y-%m-%dT%H:%M:%S", s)
          .. string.format(".%03dZ", ms)           -- ALWAYS 3 digits
   end
   ```
   Without the `%03d` pad, `"…00.9Z"` sorts *after* `"…01.0Z"` and `merge.ts:30` picks the wrong winner → a silently lost toggle. Add a fixture asserting the Lua output matches `new Date(t).toISOString()` shape for ms values 0, 5, 50, 999.
6. **Empty-array safety (critical, §9 Risk) — RECURSIVE, not top-level.** Lua/rapidjson cannot distinguish `[]` from `{}`, so a naive re-encode can turn an array into an object. Before re-encoding, **walk the entire decoded `state` tree** and force **every empty array at any depth** to encode as a JSON **array** (rapidjson array-tag), while keeping genuine objects (including `state.settings`) as objects:
   - Top-level `SYNC_TABLES` keys present in `state.data`: array-tag (even when `[]`).
   - **Nested arrays inside untouched rows** — e.g. `CareerPlan.phases` (`types/index.ts:123`) and `CareerPlan.milestones` (`:124`) — must also be array-tagged. The Kindle re-encodes the *whole* blob, and `applyState.ts:116-118` stores rows verbatim, so a nested `[]→{}` reaches the phone UI and breaks `Array.isArray`/`.map` on a table the Kindle never meant to touch. A top-level `[]→{}` is worse still: it makes the phone's 409 merge **throw** (`merge.ts:82` does `base.data.careerPlan ?? []` — `{}` is non-nullish so `?? []` won't fire — then `for (const b of base)` iterates `{}` and throws, blocking the phone's push entirely).
   - A key that was **absent** stays **absent** (never coerce missing→`[]` — `sync-core.mjs:127-135` / `applyState.ts:96-141`: that laundering is the device-wipe vector).
   - Do **NOT** use a blanket `rapidjson` `empty_table_as_array=true` — that would also turn an empty `settings` object into `[]`. The walk must be type-aware (array context vs object context), not global.
   - **Conformance fixture:** the Node→Lua→Node deep-equality test MUST include a `careerPlan` row with `phases: []` **and** `milestones: []` (nested empties) plus an empty `settings: {}`. A fixture with only top-level empties would pass and still ship the nested bug.
7. Re-encrypt `state` with a **fresh 12-byte `RAND_bytes` IV** + the same `encKey`: `blob' = base64( iv ‖ ciphertext ‖ tag )` (`EVP_EncryptUpdate`/`Final` then `EVP_CIPHER_CTX_ctrl(ctx,0x10/*GET_TAG*/,16,tagbuf)`; concat iv‖ct‖tag; standard padded base64; free the ctx). Byte-identical layout to the phone/Node path (`sync-core.mjs:102-111`).
8. `PUT /state` with `{ baseVersion, blob: blob', salt }` (echo the salt you GET'd; the Worker ignores it once set — write-once, `index.ts:198-201`).
9. **`200 {version}`** → store new `version`, update `cached_blob`, and **ACK the queue by identity, not by recordId alone.** For each intent in this flush snapshot, delete `queue[recordId]` **only if `queue[recordId].enqueuedAt == flushedIntent.enqueuedAt`**. A re-tap that arrived during the flush has a *newer* `enqueuedAt` and must **survive** for the next cycle — deleting it by recordId would silently lose the user's last action.
10. **`409 {version}`** (cloud advanced under us — `index.ts:187-188`): re-`GET /state`, re-decrypt the **fresh** remote, re-run the schema guard (step 4), re-apply the **absolute targets** with a **fresh `now`** (so the newer `updatedAt` wins `newerUpdatedAt`), re-encrypt, retry with the new `baseVersion`. Cap at **3 retries** (`MAX_PUSH_CONFLICT_RETRIES=3`, `SyncProvider.tsx:69`). Using the absolute target (never a re-flip) is essential: a 409 means the PUT did NOT apply; a naive re-toggle off the new remote could double-flip relative to intent.
11. Any failure (network, 401, >3 conflicts, schema-too-new) → **keep the queue intact**, retry next cycle. Never drop an intent on failure.

### 5.3 Explicit never-clobber rules (hard invariants)
- **Never rebuild the snapshot from the Kindle's own table list.** Only ever edit a decrypted remote blob in place.
- **Never push `[]` for a key that arrived missing.** Missing stays missing; only echo `[]` that was already `[]`.
- **Never let an array (at any depth) re-encode as `{}`.** Recursively array-tag every empty array before encoding; keep genuine objects as objects.
- **Never PUT a blob you didn't derive from a GET in the same attempt.** Always GET fresh immediately before each push attempt (incl. each 409 retry).
- **Never blind-flip on retry.** Always re-apply the absolute target.
- **Never PUT a blob whose `schema > SYNC_SCHEMA`.** Abort and keep the queue.
- **Never ACK a queue entry whose `enqueuedAt` changed since the flush snapshot.** Identity-guard the delete.
- **Never write a timestamp without 3-digit-padded ms.** Lexical = chronological is a merge correctness invariant.
- **Never write to keys outside `dailyRecords`** in the initial Phase 2 (meditation draw, settings, etc. are later, opt-in, and follow the same edit-in-place + absolute-value discipline).
- **Never persist the passphrase-derived key to disk.** Cache in memory only.

### 5.4 Device seed UUID
DailyRecord ids are **deterministic** (`date|practiceId`, `types/index.ts:43`, `useDailyRecords.ts:15`) and MeditationDay ids are deterministic (the date key) — so the Kindle **mints no entity UUIDs at all** for its in-scope writes, which is exactly what makes its writes converge with the phone without tombstone hazards. A per-device UUID seed is only needed by clients that **create** Category/Practice rows (the phone seeds those, `MEMORY.md` "per-device seed UUIDs"); the Kindle must **not** create categories/practices. Store a random `device_id` in LuaSettings purely for diagnostics/log lines, not as a row-id source.

**`lib/syncclient.lua` (the sync call — wallabag pattern)**
```lua
local http, ltn12 = require("socket.http"), require("ltn12")
local socket, socketutil = require("socket"), require("socketutil")
local rapidjson = require("rapidjson")

local M = {}
function M.get_state(url, token, meta)
  local sink = {}
  socketutil:set_timeout(10, 30)
  local code = socket.skip(1, http.request{
    url = url .. "/state" .. (meta and "?meta=1" or ""),
    method = "GET",
    headers = { ["Authorization"] = "Bearer " .. token },
    sink = ltn12.sink.table(sink),
  })
  socketutil:reset_timeout()
  if code == 401 then return nil, "unauthorized" end
  if code ~= 200 then return nil, "http " .. tostring(code) end
  return rapidjson.decode(table.concat(sink))     -- { version, blob, salt }
end

function M.put_state(url, token, baseVersion, blob, salt)  -- Phase 2
  local body = rapidjson.encode{ baseVersion = baseVersion, blob = blob, salt = salt }
  local sink = {}
  socketutil:set_timeout(10, 30)
  local code, _, _ = socket.skip(1, http.request{
    url = url .. "/state", method = "PUT",
    headers = { ["Authorization"]="Bearer "..token,
                ["Content-Type"]="application/json",
                ["Content-Length"]=tostring(#body) },
    source = ltn12.source.string(body),
    sink = ltn12.sink.table(sink),
  })
  socketutil:reset_timeout()
  if code == 200 then return rapidjson.decode(table.concat(sink)) end       -- {version}
  if code == 409 then return nil, "conflict", rapidjson.decode(table.concat(sink)).version end
  return nil, "http " .. tostring(code)
end
return M
```
Show an `InfoMessage` + `UIManager:forceRePaint()` before these blocking calls (wallabag does exactly this).

## 7. Install & config runbook

1. **Jailbreak + KOReader (one-time).** Jailbreak the Kindle, install **KUAL**, then install **KOReader** (lands at `/mnt/us/koreader/`). Launch it once from KUAL to confirm it runs.
2. **Smoke-test spike FIRST (gate before any UI work).** Drop a ~40-line `smoke.koplugin` that: (a) `require("socket.http")` GET `https://<worker>/health` and shows the result; (b) `ffi.loadlib("crypto","57")` + a known PBKDF2 test vector; (c) **allocates an `EVP_CIPHER_CTX` via `EVP_CIPHER_CTX_new` and frees it** — i.e. confirms the context-lifecycle *functions* are callable, not just the types (§4.2 plumbing note); (d) decrypts one blob produced by `node scripts/sync.mjs`. If any of these fails on this firmware, stop and resolve (different libcrypto soname, missing EVP context functions, or stripped LuaSec) before building.
3. **Build the corpus bundle.** Copy `src/data/escriva_points.json`, `rosary_contemplation.json`, `rosary_images.json`, `practice_texts.json` (and painting images) into `planoflife.koplugin/data/`. Generate Lua conformance fixtures via `node scripts/selection-fixtures.mjs`.
4. **Install the plugin.** Connect the Kindle by USB (mass storage) and copy the whole `planoflife.koplugin/` folder into `/mnt/us/koreader/plugins/`. Eject; restart KOReader (it scans `plugins/*.koplugin` at startup).
5. **Configure.** Open *Tools ▸ Plano de Vida ▸ Configurar*:
   - Worker URL: `https://planoflife-sync.<acct>.workers.dev` (the same origin the phone uses — `VITE_SYNC_URL`).
   - Passphrase: enter via `InputDialog` (`text_type="password"`) — the **same** passphrase used on the phone. The plugin derives the bearer token (310k) and enc key (600k) from it; nothing else is entered (the salt comes from the server).
   - **Check the device clock/timezone is correct (load-bearing, not cosmetic).** A wrong clock both buckets records under the wrong `today` AND can make the Kindle's write lose the phone's concurrent merge (§9). Keep NTP/auto-time on.
   - "Remember passphrase on this device" toggle: **default ON** (stored in `settings/planoflife.lua`, plaintext — same trust model as wallabag's stored credentials; this is a personal Kindle and enables offline-after-restart + background sync). OFF = re-enter each cold start, key only ever in RAM.
6. **First sync.** *Sincronizar* → spinner during the ~1-2s key derivation, then GET /state. If the phone has pushed, the checklist for today renders with live ✓/▢; meditation/rosary populate. Empty account ⇒ "no remote state yet — push from the phone first".
7. **Iterate.** Overwrite the folder + restart KOReader; check `/mnt/us/koreader/crash.log` for Lua errors.

## 9. Risks & open questions

(Top risks with mitigations are also in `topRisks`; open questions in `openQuestions`.)

- **`ffi.loadlib("crypto","57")` soname may differ per firmware build.** The KOReader build installed on the user's Kindle may bundle a different LibreSSL version (soname `.57` is from `master`; older releases differ). Mitigation: in the spike, probe the actual soname; make `lib/crypto.lua` try a small list of versions and fall back; abort with a clear message if none resolves. **This is the #1 gate.**
- **FFI EVP context functions may not be exported by KOReader's `ffi/crypto_h.lua`.** The decrypt/encrypt path needs `EVP_CIPHER_CTX_new`/`EVP_CIPHER_CTX_free` as *callable functions*, not just the opaque type. Whether KOReader already declares them is **unverified** (not in this repo). Mitigation: spike step 2c allocates + frees a context; if it fails, additively cdef the two prototypes (the structs are already declared, so only the functions are added) and ensure `free` runs on every exit incl. the `DecryptFinal rv==0` failure path to avoid a leak.
- **TLS handshake on the specific build.** Historical Kindle KOReader builds had `tlsv1 protocol error`. Mitigation: spike step 2a; if it fails, the whole pure-Lua route is at risk — re-evaluate (but LibreSSL 4.3.2 does TLS1.2/1.3+SNI, so a current build should work).
- **rapidjson empty-array/object ambiguity on re-encode (Phase 2) — at ALL depths.** Lua can't distinguish `[]` from `{}`. A careless round-trip can: (a) turn a top-level `careerPlan: []` into `{}` → the phone's 409 merge throws (`merge.ts:82` `?? []` won't fire on a non-nullish `{}`, then for-of throws); (b) turn a **nested** `CareerPlan.phases: []` / `milestones: []` into `{}` → reaches the phone UI verbatim (`applyState.ts:116-118`) and breaks `Array.isArray`/`.map`; (c) turn a missing key into `[]` → wipes every device via the destructive apply (`sync-core.mjs:136-151`). Mitigation: **recursively** array-tag every present empty array (top-level AND nested), keep `settings`/objects as objects, never coerce missing→`[]`, and do NOT use a blanket `empty_table_as_array`. Gate Phase 2 on a Node→Lua→Node deep-equality test whose fixture includes a `careerPlan` row with empty `phases`+`milestones` and an empty `settings`.
- **Timestamp lexical-ordering bug (load-bearing for merge).** `merge.ts:30-31` resolves dailyRecord conflicts by **lexical string compare** of `updatedAt`; the phone always writes exactly-3-digit ms (`new Date().toISOString()`). If the Kindle emits variable-width ms, `"…00.9Z"` sorts after `"…01.0Z"` → wrong merge winner → silent lost toggle. Mitigation: `utcIsoMillis()` zero-pads ms to 3 digits (`string.format(".%03dZ", floor(usec/1000))`) and is conformance-tested against `Date.toISOString()` shape.
- **Journal ACK lost-update.** The queue is keyed by `recordId` and a re-tap overwrites the entry; if the ACK deletes "the intents in this flush" by recordId, a re-tap that arrived during the flush is silently lost. Mitigation: identity-guard the delete on `enqueuedAt` (delete only if unchanged since the flush snapshot); keep newer re-taps for the next cycle.
- **Clock/timezone skew → wrong "today" AND wrong merge winner.** DailyRecord ids are `localdate|practiceId`, so a wrong date writes under a bucket the phone won't reconcile. Additionally, a Kindle clock **behind** the phone makes its fresh write LOSE the phone's concurrent 409 merge (`merge.ts:30` keeps the higher `updatedAt`) even when the Kindle action is the user's latest intent → silent revert. Mitigation: show the resolved `today` in the title; warn if the clock looks off; document that **keeping the Kindle clock correct (NTP/auto-time) is load-bearing for merge correctness, not just date bucketing.**
- **Worker read-modify-write is non-atomic (inherent KV+LWW).** `index.ts:183-185` reads the version then writes; two racing PUTs can both return `200` with only one persisted. Combined with ACK-on-200, a racing Kindle write could be dropped without retry. Accepted for a single user (the two clients rarely PUT in the same ~100ms), but documented; the local journal + view-open re-sync limits the blast radius.
- **Background sync is unreliable.** Kindle sleeps aggressively and WiFi is usually off; `scheduleIn` timers don't run while suspended. Mitigation: rely on view-open / `onResume` / `onNetworkConnected` triggers, not a true background loop; the local journal makes taps instant regardless.
- **Passphrase at rest.** "Remember passphrase" stores it plaintext in LuaSettings (same as wallabag credentials). Mitigation: make it a clear toggle; OFF keeps the key in RAM only; document the tradeoff.
- **`normalizeName` NFD in Lua.** Special-reader routing and seed dedupe depend on `lowercase+NFD+strip-combining+trim`; Lua has no built-in NFD. Mitigation: prefer bundled utf8proc via FFI if exposed (verify on device); otherwise ship an explicit Portuguese accent→base map (ç,ã,á,é,í,ó,õ,ú…) plus strip `U+0300–U+036F`; conformance-test against the TS `normalizeName`.
- **740 KB `escriva_points.json` load.** Memory/latency on a low-RAM Kindle. Mitigation: load lazily only when the meditation view opens; `rapidjson.load` streams from file.

**Open questions** are listed in the `openQuestions` field.
